## 실행 기록

- 디버그 APK 빌드 및 서명 검증, JVM 테스트 38개, Android Lint 오류 0건.
- Android 16(API 36) 에뮬레이터에서 첫 권한 안내, 접근성 서비스 연결과 응답 시각 표시를 확인했습니다. 오늘 첫 화면의 건수·시간·앱별 합계, 제한의 기본 50회·자정 초기화 안내, 기록의 일·주 및 이전 주 이동을 실제 화면의 계층으로 확인했습니다.
- 한국어 인스타그램 형태의 합성 앱에서 게시물·릴스 카드 위의 접근성 가림 창과 상단 카운터 창을 확인했습니다. 설치 앱 선택기로 합성 유튜브 패키지를 연결했습니다. 해당 패키지의 커뮤니티 게시물 위 가림을 탭했을 때 Android 기기 안의 SQLite에 유튜브 게시물 열람 1건과 열람 시간이 기록됐습니다. 홈 위젯 제공자는 시스템에 등록됐으며 런처에서 추가·표시하는 테스트는 남아 있습니다.
- 일반 프로세스 종료를 재현하기 위해 테스트 APK의 PID에 SIGKILL을 보냈습니다. Android 16이 새 PID로 접근성 서비스를 다시 연결했고, 유튜브 사용자 지정 패키지를 포함한 설정이 유지됐습니다.
- 에뮬레이터의 System UI·런처·미디어 제공자가 부팅 중 멈췄습니다. 일반 영상 재생과 쇼츠 연속 재생의 Android 16 현장 검증은 끝까지 진행하지 못했습니다. 재생·정지·연속 스크롤·한도 전환은 위 JVM 상태 테스트로 확인했습니다. 아래 실기기 장시간 테스트는 남아 있습니다.

## 기기별 확인 범위

- 뷰 ID, 영상 상태, 스크롤 이벤트가 숨겨진 앱 버전은 일부 항목을 놓칠 수 있습니다. 사용 중인 인스타그램·X 수정 버전과 유튜브 리밴스드 3차 수정 버전, Galaxy의 장시간 절전 동작은 실제 기기에서 재검증해야 합니다.
- 뷰어가 로딩 중 항목 식별 정보를 나중에 노출하면 가림이 한 번 더 뜰 수 있습니다. 가림 레이어는 콘텐츠 영역을 덮습니다. 뒤에서 재생하는 오디오, 녹화 방지 창, 강제 종료 같은 Android 상태는 대상 앱과 시스템이 제어합니다.
- 위젯은 자정 갱신을 예약합니다. 기기의 절전 상태에 따라 런처에 반영되는 시점이 늦어질 수 있습니다.

## Android 16에서 재검증하는 방법

1. 접근성 서비스를 켠 상태로 앱 정보의 배터리 상태와 Bluemind의 마지막 응답을 확인합니다.
2. 실제로 쓰는 수정 APK를 각각 선택합니다. 인스타그램은 피드, 검색/탐색, 프로필, 친구가 보낸 릴스 링크 및 직접 릴스 탭을 따로 열어 확인합니다. 틱톡 사진·텍스트, 유튜브 일반 영상·쇼츠·커뮤니티, X 인용·답글·공유도 확인합니다.
3. 피드에서 가려진 미리보기가 재생돼도 횟수가 그대로인지 봅니다. 일시정지 상태에서 승인하고, 재생할 때 1회 증가하는지 봅니다. 멈추고 재개하거나 자동 반복할 때 추가 집계되지 않아야 합니다.
4. 일일 제한을 작게 설정한 뒤 쇼츠 뷰어 안에서 넘깁니다. 마지막 허용 영상은 계속 보이고 다음 영상과 다른 진입 경로는 막혀야 합니다. 알림 모드의 시간창 규칙은 알림만 표시되어야 합니다.
5. 증상이 발생하면 Bluemind 설정의 최근 종료 이유와 마지막 응답 시각을 확인합니다. PC에서 `adb shell dumpsys accessibility`, `adb shell dumpsys activity exit-info com.bluemind.app`, `adb logcat -b crash`로 시스템의 연결 및 종료 상태를 확인할 수 있습니다.
